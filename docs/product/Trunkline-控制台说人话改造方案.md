## 三、P1+：运维工作台（新运维首页）

**路由** `/ops-home`，菜单「团队」组第一项，标题「运维工作台」，roles=ops/admin。技术总览原位置由它接管。

**布局（三区，全部只读聚合，前端并发调现有接口，零后端改动）**：

1. **今日状态一句话**（绿/黄/红状态灯）：
   - 绿：「今天全公司调用 N 次、花费 ¥X，一切正常」
   - 黄：「一切正常，但有 N 件事需要处理」→ 待办区
   - 红：「有 2 个模型被自动停用」→ 高亮待办
2. **待办列表**（每条可点击直达处理页）：
   - 模型被自动停用 → 去接入管理处理
   - 密钥 7 天内到期 N 把 → 去全部密钥续期
   - 员工额度用超 80% 共 M 人 → 去调额度
   - 失败率比昨天明显升高 → 去调用观测
3. **五条动线快捷入口卡**：接新厂商（接入管理）/ 给员工发密钥（全部密钥）/ 看今天用量（团队用量）/ 查调用记录（调用观测）/ 调整额度（全局配置）

**对应运维五条动线**（本方案梳理结论）：
① 接入：接厂商→建分组→员工用上（现分散 3 页，工作台入口 + 接入管理页内步骤指引缓解）；② 授权：开账号→发密钥→看使用；③ 看板：花多少→谁最多→有无异常；④ 救火：发现故障→换渠道/调比例→通知（状态监控与接入管理/虚拟模型之间补互跳按钮）；⑤ 管钱：设额度→看账单→超了处理。

## 六、管理员视角业务流程梳理（本轮补齐）

管理员与运维的差异任务四条动线：

1. **人员**：建账号/批量导入 → 分角色（员工=我的 / 运维=我的+团队 / 管理员=全部）→ 离职停用。现状基本人话 ✅。
2. **安全合规**：审计日志查「谁改过配置、谁登过、谁被拒过」→ 风险等级筛查 → 异常处置。痛点：事件类型/资源ID 偏技术（§四-6 已列）；「谁该用这页」无引导。
3. **平台治理**：全局配置定默认 → 个别模型到模型库覆盖 → 改坏了用配置版本回滚。痛点：**全局配置与厂商与模型库的覆盖关系无任何页面说明**，管理员不知道改哪处生效。方案：全局配置页头加一句「这里的设置对所有模型生效；要单独调某个，去厂商与模型库」（globalSettings.json 里已有此文案 ✅，在模型库页反向补一句「没单独设置的，走全局配置的默认值」）。
4. **厂商资产**：厂商与模型库维护（§四-4）。

管理员痛点与运维重合的部分（接入/看板/救火/管钱）沿用 §三运维工作台；管理员额外在工作台看到「需要管理员处理」的待办（如账号锁定、审计风险事件）——**待办列表按角色过滤，同一组件两角色复用**。
