# Trunkline 社区版完善规划

> 定位：社区版是获客漏斗与信任地基（Apache-2.0 全量开源，不藏关键功能）。
> 本文件是社区版专项规划，与 `Trunkline-产品迭代计划.md`（主计划，与本文件同目录）配合使用：
> 主计划管版本节奏与任务号，本文件管社区版的**目标、补强项与验收标准**。二者冲突时以主计划任务号为准。
> 创建：2026-11-03 · 基于代码实况探查 + 产品评估 + UI 走查
> **版本号说明**：产品版本号冻结在 **0.1.0**——下文 v0.2.0~v0.5.0 是阶段名而非发布版本号；社区版完善（§五验收清单全过）后才升版，届时品牌/版本号统一动作（pom、镜像 tag、CHANGELOG 首版）一并执行。

## 一、社区版要赢的三个指标

| 指标 | 定义 | 目标 | 为什么 |
|---|---|---|---|
| **TTV**（Time-to-Value） | `docker run` → 接入首个厂商 → 发出第一把密钥 → 员工发出第一句对话 的总时长 | ≤ 10 分钟 | 漏斗第一环的转化率代理指标；每多一步，自建用户流失一截 |
| **员工激活率** | 部署后 7 天内实际发起过调用的员工数 / 总账号数 | ≥ 60% | 续费由「员工真的在用」决定，员工不用 = 部署变摆设 |
| **值班自足率** | 运维不经作者介入、仅凭控制台即可发现并恢复故障的比例 | ≥ 90% | 告警主动推送（Webhook）已决策归商业版（见 `editions.md`）；社区版承诺「打开控制台就能看清故障」，主动报信归 ENT |

**社区版不背的指标**：付费转化（那是 ENT 版与销售的事）、多租户、SSO（ENT 专属，见 `editions.md` 边界）。

## 五、验收清单（社区版 v0.5.0 完成时逐项核对）

- [ ] 新环境 `docker run` → `ttv-check.sh` 全绿且总耗时 ≤ 10 分钟
- [ ] 断开一个上游实例，运维打开控制台首页或状态监控页，**无需翻菜单**即可看到熔断/下线的告警信息
- [ ] 管理员接入一个新厂商全程只填 ≤ 8 个必填字段
- [ ] 三张核心表格首屏 ≤ 7 列、无横向滚动
- [ ] 员工侧 grep 禁用词（Token/IP Hash/令牌桶/OPEN/CLOSED/权限码）零命中
- [ ] 员工从扫码到发出第一句对话 ≤ 3 步操作
- [ ] `views/_attic/` 外无不可达页面文件
