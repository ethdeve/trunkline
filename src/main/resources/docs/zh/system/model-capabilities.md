# 模型能力档案与一键虚拟模型

> v0.2.0 新增。看每个模型擅长什么；按用途一键建虚拟模型池与路由规则。仅运维和管理员可用。

## 这两个页面是干什么的

「团队」组里新增了两个入口：

- **模型能力档案**：静态画像浏览页，按用途、厂商、服务类型、偏好强度筛选，回答「选哪个模型」。
- **场景模板**：一键虚拟模型向导，选一个用途 → 预览将创建的池和规则 → 一键应用，回答「怎么把选好的模型配起来」。

两者都在 OSS 主干实现，企业版随 jar 天然继承，不需要企业侧再做一遍。

## 模型能力档案怎么用

1. 进入「团队 → 模型能力档案」。
2. 用顶部筛选器选用途（如「客服问答」）、厂商、服务类型、偏好强度、最慢延迟，点「筛选」。
3. 表格里「模型 / 标准型号」一列显示接入名和归一后的标准型号；「强度」是代码 / 中文 / 数学 / 推理四档评价；「来源」说明这条画像的出处。

关于来源：随包发布的是内置基线（`builtin`），只收录公开可查的通用能力，不确定的维度显示「未知」而不是「不支持」。DTO 还预留了 `persisted` / `resolver` / `probe` / `spi` 四种来源标记，用于现场维护、名称识别、主动探测和企业注入；当前版本只有内置基线实际生效，前端会如实显示每一条的来源，不会把推测值当成厂商承诺。

价格不入画像：价格随厂商频繁变动，系统已有成交价快照机制处理，静态档案写入即过时。

## 一键虚拟模型怎么用

1. 进入「团队 → 场景模板」，左侧选一个用途；也可以从顶栏问号图标的接入指南页进入。
2. 点「预览将创建的配置」，查看系统准备建的池和规则：池名就是之后调用时用的 `model` 值；规则动作里的目标模型名已经换成真实池名，不是模板里的示例值。
3. 确认后点「一键应用」。池和规则会写库并热生效，不需要重启。
4. 用结果页给出的 `model` 值发一条真实请求，确认路由生效；也可以到「虚拟模型」和「路由规则」页查看刚创建的配置。

内置四个场景覆盖不同组合形态：

| 场景 | 会创建什么 | 验证点 |
| --- | --- | --- |
| 客服问答 | 1 个 chat 池 + 池级限流规则 | 画像选模 + 规则注入真实池名 |
| 文档检索 RAG | chat / embedding / rerank 三个池 + 三条按服务类型路由的规则 | 多池组合，画像选模差异可实测 |
| 代码助手 | 1 个 chat 池 + 模型重写规则 | 主观强度（code）参与选模 |
| 成本护栏 | 不建池，只生成一条全局限流规则 | 「场景只出规则」的路径 |

## 注意事项

- **画像未命中会降级**：如果画像库里没有匹配的模型，系统使用对应服务类型的第一个已接入实例，并在结果里标注「未命中画像」，不会伪造画像数据。
- **没有接入实例就跳过**：某个服务类型还没有接入任何模型时，对应池不会创建，依赖它的规则也会跳过，避免落一条永远命中不了的配置。
- **重复应用会跳过同名池**：池已存在时在「注意 / 跳过项」里给出提示，其余项继续创建，不会因为部分失败就整体报错。
- **限流阈值需要现场调整**：成本护栏和客服问答里的容量 / 速率是示例值，请按实际容量修改后再长期保留。
- **租户隔离**：池和规则沿用既有的租户持久化链路，新建配置只属于当前租户；画像基线是全局只读数据。
