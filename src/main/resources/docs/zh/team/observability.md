# 调用观测

> 谁在什么时候调了什么，失败的那次为什么失败。

## 这个页面是干什么的

这一页把每一次调用记成一行。默认「调用历史」，可以按人、模型、调用编号搜索，只看失败的记录，点开「详情」看这次请求到底卡在哪。有相应权限的话还能看到「调用分析」和折叠的「高级：追踪管理」。

## 什么时候会用到

- 员工报「刚才那次报错了」，要查原因
- 想知道某段时间失败多不多
- 要导出记录做对账或复盘
- 想看一次请求经过了哪些步骤

## 页面上有什么

| 你看到的东西 | 是什么意思 |
| --- | --- |
| 调用历史 | 时间、调用编号（Trace ID）、员工请求的虚拟模型、实际路由到、调用方、耗时、状态 |
| 只看失败 / 全部调用 | 一键过滤失败记录 |
| 查询 / 重置 / 导出 | 按时间、状态、关键词查；导出 CSV（Excel 可直接打开）或 JSON |
| 详情 | 请求路径、状态码、错误码、失败原因、用量统计、限流 / 熔断状态、客户端 IP、API Key 等 |
| 调用分析 | 总追踪数、错误追踪、平均耗时、记录比例，按权限显示 |

## 常见操作

**查一次失败**

1. 切到「只看失败」
2. 选时间范围（最近 1 小时 / 24 小时 / 7 天）
3. 输入人名或模型名，点「查询」
4. 点该行「详情」或调用编号，看失败原因

**导出记录**

1. 设好筛选条件
2. 点「导出」
3. 选 CSV 或 JSON

## 遇到问题先看这里

**没有失败记录**

说明筛选条件下全部成功了；把状态切回「全部」即可看到所有记录。

**提示「没有查看调用历史的权限」**

需要管理员给你的账号加权限。

**找不到「高级查询」**

这个页签已经下线，功能合并进调用历史和调用分析。

## 还是要人帮忙？

报障时给出**调用编号（Trace ID）**、发生时间和报错文字，管理员能直接定位。
